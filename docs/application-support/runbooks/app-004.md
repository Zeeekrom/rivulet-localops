# APP-004 · Configuration or permission failure

- **Symptom:** configuration health is `unavailable`; the release label is invalid or the ledger directory is not
  writable by the runtime identity.
- **Impact:** readiness fails before unsafe or unaudited work is accepted.
- **Severity:** SEV-3, raised to SEV-2 if all instances are affected.
- **Detection:** use the configuration component's booleans; Support Bundle output does not reveal paths or raw
  environment variables.
- **Diagnosis:** compare allowlisted deployment values with IaC, then validate the non-root container identity and its
  single writable runtime directory.
- **Root cause:** invalid bounded configuration, wrong ownership/mode, missing mount or an unreviewed deployment change.
- **Resolution:** restore the expected release value or minimum required filesystem permission; do not grant broad
  administrator/root access.
- **Rollback:** redeploy the last verified configuration/image through Bicep when a narrow correction is not safe.
- **Verification:** configuration and build/version components are healthy; the runtime remains non-root; smoke and
  ledger integrity pass.
- **Escalation boundary:** escalate changes to identity, secrets, mounts or hosting policy to the platform owner.
- **Lessons learned:** report validity and access checks, not secret values or internal paths.
