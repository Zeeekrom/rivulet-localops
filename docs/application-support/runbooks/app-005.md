# APP-005 · Provider unavailable and manual fallback

- **Symptom:** provider health is `degraded`, diagnosis/submit returns manual fallback, or the kill switch is enabled.
- **Impact:** automated diagnosis pauses; accountable manual handling continues.
- **Severity:** SEV-2 when provider use is intentionally blocked across the service.
- **Detection:** check provider component state, control-event ID and the request's correlation ID.
- **Diagnosis:** determine whether the kill switch was deliberate or the dependency/provider failed. Do not bypass the
  switch to make a smoke test pass.
- **Root cause:** operator control, dependency outage, provider identity mismatch or capability failure.
- **Resolution:** keep requests in manual fallback, repair/validate the provider, then re-enable it with an accountable
  operator and reason.
- **Rollback:** disable the provider again if recovery verification fails.
- **Verification:** every fallback adds an audit event without storing raw request text; ledger integrity remains true;
  a post-recovery submission succeeds.
- **Escalation boundary:** escalate identity, security or external-provider failures; do not grant wider agent tools.
- **Lessons learned:** provider availability must not determine whether an audit trail exists.
