# APP-003 · Ledger integrity failure and restore

- **Symptom:** `database_ledger` is `unavailable`, integrity is false, or a write returns
  `ledger_integrity_failure`.
- **Impact:** automated writes and decisions stop. The system fails closed to protect the audit chain.
- **Severity:** SEV-2.
- **Detection:** use `/ops/v1/health` and `/ops/v1/ledger/integrity`; record the first invalid sequence without copying
  payload contents.
- **Diagnosis:** work only on an isolated copy. Compare backup integrity, event count and hash-chain result.
- **Root cause:** distinguish payload/hash tampering, storage corruption and permission/storage availability failures.
- **Resolution:** stop writers, select a previously verified backup and use the offline atomic restore path.
- **Rollback:** preserve the affected file as restricted evidence; never rewrite hashes to make corrupted history pass.
- **Verification:** restored chain is valid, event count matches the backup, health returns 200 and a bounded smoke
  request succeeds.
- **Escalation boundary:** escalate if no verified backup exists, evidence may represent malicious activity, or recovery
  would discard legitimate events.
- **Lessons learned:** backups are useful only when their hash chain and recovery procedure are both tested.
